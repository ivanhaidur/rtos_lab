# Лабораторна робота №1 — Вступ у FreeRTOS

Три періодичні задачі на симуляторі FreeRTOS (порт **WIN32-MingW**, також збирається під Linux POSIX). Кожна задача виконує «роботу» тривалістю *Cᵢ* і логує тіки старту/фінішу. Проєкт дає змогу порівняти джитер початку періоду при `configUSE_TIME_SLICING = 1` і `0`.

## Варіант (ID = 2)

| Задача | Період *Tᵢ*, мс | Робота *Cᵢ*, мс | Пріоритет |
|--------|-----------------|-----------------|-----------|
| τ1 (`HAIV_T1`) | 13 + (2 mod 7) = **15** | 2 + (2 mod 3) = **4** | 3 (найвищий) |
| τ2 (`HAIV_T2`) | 21 + (2 mod 5) = **23** | 3 + ((2/3) mod 3) = **3** | 2 |
| τ3 (`HAIV_T3`) | 34 + (2 mod 9) = **36** | 4 + ((2/5) mod 3) = **4** | 1 (найнижчий) |

ID mod 2 = 0, тому τ1 > τ2 > τ3. Завантаження процесора U = 4/15 + 3/23 + 4/36 ≈ 0.508. Гіперперіод НСК(15, 23, 36) = 4140 мс; саме стільки триває експеримент, після чого програма друкує таблицю й завершується.

```

├── build.bat            — збірка під Visual Studio (MSVC) і запуск

├── run_1_variant.bat    — пріоритети за варіантом, TIME_SLICING = 1
├── run_2_equal_ts1.bat  — рівні пріоритети, TIME_SLICING = 1
├── run_3_equal_ts0.bat  — рівні пріоритети, TIME_SLICING = 0
├── run_all.bat          — усі чотири запуски по черзі
```

Ядро FreeRTOS у репозиторій не входить; його беруть з офіційного репозиторію.

## Як запустити (Windows, Visual Studio)

Потрібна Visual Studio з робочим навантаженням «Desktop development with C++».

1. Покладіть цей проєкт у `FreeRTOS/FreeRTOS/Demo/Lab1_FreeRTOS` (поруч із `WIN32-MSVC`).
2. Двічі клацніть `run_1_variant.bat`, `run_2_equal_ts1.bat` або `run_3_equal_ts0.bat`.
   Скрипт сам знайде Visual Studio, збере програму, запустить її та збереже журнал і скриншот у `results/`.

З командного рядка:

```bat
build.bat          :: пріоритети за варіантом, TIME_SLICING=1
build.bat 1 1      :: рівні пріоритети, TIME_SLICING=1
build.bat 1 0      :: рівні пріоритети, TIME_SLICING=0
```

## Як запустити (Windows, MinGW)

1. Встановіть [Git](https://git-scm.com/) і [MSYS2](https://www.msys2.org/). У терміналі MSYS2 MinGW64 виконайте `pacman -S mingw-w64-x86_64-gcc make`.
2. Завантажте FreeRTOS:
   ```bash
   git clone https://github.com/FreeRTOS/FreeRTOS.git
   cd FreeRTOS
   git submodule update --init --recursive
   ```
3. Склонуйте цей проєкт у каталог демо, поруч із `WIN32-MingW`:
   ```bash
   cd FreeRTOS/Demo
   git clone -b lab1 https://github.com/ivanhaidur/rtos_lab Lab1_FreeRTOS
   cd Lab1_FreeRTOS
   ```
4. Зберіть і запустіть:
   ```bash
   make run PREFIX=HAIV_
   ```

Якщо ядро лежить в іншому місці, вкажіть шлях до каталогу з `tasks.c`:

```bash
make run FREERTOS_KERNEL=/c/src/FreeRTOS/FreeRTOS/Source
```

У Linux/macOS команди ті самі, Makefile сам обирає порт POSIX.

## Режими експерименту

| Команда | Пріоритети | Time slicing |
|---------|------------|--------------|
| `make run` | за варіантом (3/2/1) | 1 |
| `make run EQUAL=1 TIME_SLICING=1` | усі рівні (2/2/2) | 1 |
| `make run EQUAL=1 TIME_SLICING=0` | усі рівні (2/2/2) | 0 |

Додаткові параметри: `VERBOSE=0` друкує лише підсумок, `PREFIX=ABCD_` задає префікс імен задач.

## Як це працює

- **Період.** Задача блокується через `xTaskDelayUntil(&xLastWake, Tᵢ)`, тож моменти звільнення (release) не «пливуть». Усі задачі вперше звільняються в t = 0 (критичний момент).
- **Робота Cᵢ.** `vApplicationTickHook()` на кожному тіку збільшує лічильник задачі, яка саме виконувалась. Busy-loop `prvDoWork()` крутиться, доки власний лічильник не зросте на Cᵢ. Тому витіснення не «з'їдає» роботу: задача отримує рівно Cᵢ мс процесорного часу.
- **Журнал.** Після кожної роботи задача кладе запис `{release, start, finish}` у чергу. Друкує лише задача-логер з пріоритетом idle, тож `printf()` не впливає на часову поведінку задач.

Приклад рядка журналу:

```
HAIV_T2   job=3    release=46    start=49    finish=52     S=3  R=6
```

`S = start − release` — затримка старту, `R = finish − release` — час відгуку. Джитер старту — `Smax − Smin`.

## Результати (Windows, MSVC, 4140 мс)

| Режим | τ1 джитер | τ2 джитер | τ3 джитер | Rmax τ1/τ2/τ3 |
|-------|-----------|-----------|-----------|----------------|
| Пріоритети 3/2/1, TS = 1 | 0 | 4 | 7 | 4 / 7 / 11 |
| Рівні, TS = 1 | 1 | 1 | 1 | 11 / 10 / 11 |
| Рівні, TS = 0 | 6 | 7 | 4 | 10 / 10 / 8 |

Значення наведено без першої роботи: симулятор Windows запускає першу задачу із затримкою близько 2 мс.

Пропусків дедлайнів немає в жодному режимі. При рівних пріоритетах вимкнення квантування збільшує джитер старту з 1 до 4–7 мс: щойно звільнена задача чекає, доки поточна завершить свою роботу. Натомість роботи не переплітаються, тож максимальний час відгуку менший (8–10 мс замість 10–11 мс).
